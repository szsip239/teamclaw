# 我弄了个开源项目，想把 AI Agent 从“个人玩具”变成“企业可管理的资产”


## 让人倒吸一口凉气的现状

AI Agent 这玩意儿，技术上早就不新鲜了。像 OpenClaw 这种开源网关，底子打得很厚实——接模型、调工具、跑沙箱，十八般武艺俱全。

一说OpenClaw，大家在网上玩的热火朝天，一问都在“拥抱 AI”——研发拿 Claude 摸鱼写代码，市场用 GPT 凑策划案，连老板自己都搞了个 DeepSeek 玩得不亦乐乎。

但你往企业里瞅一眼，实际用起来那是相当狂野：

张三在自己电脑上捏了个手感极佳的 Agent，连着公司的 API Key 跑得飞起。结果他一离职，这套“祖传 Prompt”当场下落不明。
李四在隔壁部门又重新踩了一遍张三踩过的坑，耗了半个月，调出了个差不多的玩意儿。俩人甚至都没加过微信。
至于老板？老板只知道公司每个月都在给大模型充钱，但到底用出了什么花？有没有把公司机密喂给 AI？一问三不知。

**Agent 和牛逼的技能（Skills）全玩在个人手里，始终没变成公司的“硬资产”。** 这事儿不管怎么想，都有点离谱。

---

## 我到底想干嘛？

我觉得，AI Agent 不该是个别极客自娱自乐的玩具，它得像公司里的电脑、服务器、ERP 系统一样，被明明白白地管起来。

注意，管理不是为了设卡子不让用，恰恰相反，是为了让大家能**放心大胆、有组织有纪律地用**：

- 张三调教好的“金牌打工人 Agent”，全公司点开就能用。
- 部门里沉淀了一手好技能，直接扔进公共库，成为团队知识库的一部分。
- 谁喜欢用啥模型，哪项业务最吃算力，老板能在后台看得心里亮堂。
- 哪怕是刚毕业的实习生入职第一天，打开浏览器也能直接用上前辈们留下的极品 Agent，做到“开箱即用”。

这就是我搞 **TeamClaw** 的初衷：**把散落在员工电脑里的“游击队”，整编成企业的“正规军”。**

---

## 站在巨人的肩膀上：为什么选 OpenClaw？

原因很实在：**它把最脏最累的活儿给包圆了。**

怎么连模型、怎么弄隔离沙箱、怎么做底层通信，这些硬骨头它啃得非常好。如果我们自己从头造轮子，那纯属吃饱了撑的。

**但 OpenClaw 的毛病在于：它太单纯了，没吃过“企业级社会”的苦。** 
它原生只顾着自己单机跑得爽，没有多租户、没有细粒度权限、没有行为审计。这不怪它，人家生来是个“运行时”，而不是个“大管家”。

所以 TeamClaw 的定位很明确：**绝不在这堆底层代码里重复造轮子，我们就站在 OpenClaw 的肩膀上，专心把企业需要的“管家式服务”给做出来。**

这玩意都是Claude生成的，我只是个产品经理。但是每个开发阶段都与Claude做了完整详细的沟通，他出的Plan非常详细，代码质量也很高，缺点是修错的时候有时候需要好几次，特别是到了后期模块多了以后，你加了一个功能很可能会带出一堆BUG
